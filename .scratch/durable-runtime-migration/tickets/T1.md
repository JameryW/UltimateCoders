## What to build

新执行信封 + 契约握手（一刀切，无兼容窗口）：
1. 派发信封定义（proto + worker payload）：`graph_id / node_id / attempt_id / idempotency_key / worker_epoch / contract_version`。
2. 注册/心跳握手：worker 上报 `contract_version`；gateway 拒绝不匹配版本的注册与派发并明确报错（消灭混跑静默假死）。旧版 worker 在 gateway 升级后必须被握手拒入（D7 已核定这是升级顺序安全的依据）。
3. `idempotency_key` 规范定义：graph+node+attempt 确定性派生，禁用时间戳成分（现状 message_id 含 millis，重发即新键）。
4. 过渡期最小桥：图存在之前按恒等映射发信封（graph_id=task_id、node_id=subtask_id、attempt_id=本地 retry 序号）；旧字段仅作过渡，T4 落地时删除。
