## 与票面假设的偏差（实现时注意）

1. proto 无 node/attempt 标识符消息——CancelTaskRequest 扩展用可选字段，不复用不存在的 NodeIdentifier。
2. NatsTaskEvent 缺 node/attempt 字段——扩展 schema 或约定 data map；命名对齐裁决：**控制面沿用 `subtask_id` 槽位承载 node_id**（graph_id == task_id 身份映射 T6 已确立），attempt 用序号（对应 dispatch_retry_count）。
3. Python worker 无进程组 kill——需 spawn `start_new_session=True`（POSIX）+ (task,node)→proc 登记 + os.killpg；Windows 开发环境 fallback 单进程 kill（生产 worker 跑 POSIX）。
4. `fail_running_attempts` 是 graph 整批原语——单节点 cancel 需新签名；**budget 语义需考证**：若 cancel 复用 fail_attempt 会烧 retry 预算，与"取消不惩罚"直觉冲突——设计点见 PRD。
5. TS subtask 级 cancel 纯本地——换新 verb 后 control-outcome.test.ts 的本地语义测试受影响。
6. 其余与票面一致（uc.task.event core pub/sub、pause-grace seam、diamond 测试存在）。
