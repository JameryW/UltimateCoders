## 1. Rust：heartbeat monitor 与 legacy reaper（C1 对象）

- `spawn_heartbeat_monitor`：`crates/uc-grpc/src/server.rs` L3212-3304。30s tick。
  现行为：`mark_stale_tasks_failed` → `mark_stale_workers` + `reassign_stale_subtasks`
  （dead-worker 路径，L3237）+ registry 注销（L3242-3248）+ 受影响 task 逐个
  `dispatch_ready_subtasks`（L3257-3265）→ `reassign_stale_assigned_subtasks(300s)`
  （L3294）+ 重派（L3297-3300）。
- 不可重入陷阱：tokio::sync::Mutex，分支间必须 `drop(store)` 再重锁
  （L3272-3280 注释，否则首个 clean tick 死锁整个 monitor）。
- `reassign_stale_subtasks`（TaskStore impl，server.rs，尾段 L1799-1802）：回退
  Pending + persist + `fanout_graph_fail(reason="stale_worker")`。
- `reassign_stale_assigned_subtasks`：L1899 起，基于 `assigned_subtask_times`
  （`update_subtask_status` L1876-1881 维护）。
- `get_ready_subtasks`：L1816-1844（server.rs 内 TaskStore impl）。**pause 闸就在这**：
  task.status != InProgress → 空；subtask Pending + 依赖全 Completed。
- `publish_ready_subtasks`：L2477-2609。dispatch_gate（能力 + contract_version 双闸）；
  retry_count>=3 → Failed；Remote 发布失败 → increment/revert；PreferRemote → 回
  Pending。生产调用点唯一：update_task RPC L4631。`dispatch_ready_subtasks` L3311+
  为 NATS 订阅路径镜像。
- 删除对象单测：L6028-6120（reaper 四测）+ L7794 `graph_fail_verbs_fire_at_reaper_waypoints`。

## 2. Rust：graph-plane reaper 能力确认（C1 前提，已确认可行）

- `timeout_sweep`（graph_store.rs L1478-1510）：扫 `task_attempts WHERE status='RUNNING'
  AND COALESCE(heartbeat_at, started_at) < NOW()-timeout` → 逐个 `fail_attempt`；
  返回实际 swept 的 attempt id（Fenced 排除）。**当前无生产调用方**（仅集成测试
  graph_store_integration.rs L1629/L1650/L1687 + server.rs L807 注释引用）。
- `fail_attempt`（L1455-1470 + fail_attempt_tx L1641+）：attempt FAILED + fence
  （下一次 schedule_attempt 带 max(worker_epoch)+1）；预算内（retry_no <
  max_attempts-1）node 回 READY，否则 node FAILED。`DEFAULT_MAX_ATTEMPTS=3`（L1534）。
- **覆盖面确认**：`schedule_attempt`（L1112-1234）直接以 `'RUNNING'` 建 attempt 行
  （L1203），started_at=NOW() → Assigned-未拾起（stale-Assigned）与 dead-worker
  （心跳停止）两个 legacy 场景都被 sweep 的 COALESCE 窗口覆盖；
  `node_state_token("Assigned")="RUNNING"`（L118）；
  `transition_ok("RUNNING","READY")` 是合法的 fence re-arm edge（L2035）。
- `recompute_ready`（L1519-1526）：CREATED + 依赖全 SUCCEEDED（或 SKIPPED+optional）
  → READY。同样无生产调用方（T6 派发权威仍在 legacy get_ready_subtasks；graph 侧
  verbs 由 legacy 突变 fanout：schedule L792 / heartbeat L808 / commit L817 / fail L834）。
- **桥接缺口（C1 要补的）**：sweep 只改 graph 行；legacy HashMap 状态与重派需 monitor
  侧驱动 → sweep 返回值需带 (graph_id, node_id, attempt_id, FailOutcome)。
- NodeRow（L168-176）：node_id/state/dependencies/required_capabilities/effect_class，
  **无文件列**；graph_nodes 表（L518-535）亦无 → C5 conflict_risk 不进 schema。

## 3. Rust：pause/resume RPC 现状（C4/D6 依据）

- `pause_task` RPC：server.rs L4343-4385；`resume_task` RPC：L4387-4457。
  均走 legacy `TaskStore.pause_task/resume_task`（task_store.rs L523/L542）+ 事件广播 +
  NATS status event + resume 侧 checkpoint drift 告警（advisory）。
- **缺口**：resume RPC 不调 `publish_ready_subtasks` → D6 "resume=从 NodeCompletion
  重推 READY" 需在 resume 成功后补重派。
- D6 ①"pause=图级停派闸（Rust 现行为即如此）"成立：get_ready_subtasks 要求 InProgress。
